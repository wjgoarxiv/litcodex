## 함수 종속의 정의와 표기

학번 → 이름, 학과    과목 코드 → 과목명, 담당 교수

- **함수 종속** 열 A의 값이 정해지면 열 B의 값이 하나로 정해질 때 A → B라고 쓴다
- **결정자** 화살표 왼쪽의 열, 예에서는 학번과 과목 코드
- **종속자** 화살표 오른쪽의 열, 결정자가 같으면 언제나 같은 값을 가진다
- **기본 키** 행 하나를 유일하게 가리키는 열의 묶음, 원본 표에서는 (학번, 과목 코드)
- **부분 종속** 기본 키의 일부만으로 결정되는 열, 이름은 학번만으로 정해진다
- **이행 종속** A → B이고 B → C라서 A → C가 되는 경우
- **읽는 법** 화살표 하나가 표 하나의 후보가 된다고 보면 분해가 쉬워진다
- **확인 방법** 같은 결정자 값을 가진 행들의 종속자 값이 모두 같은지 본다
- **주의** 지금 자료에서 우연히 같은 값은 종속이 아니다, 규칙으로 늘 성립해야 한다
- **예외** 동명이인이 있으므로 이름 → 학번은 성립하지 않는다
- **후보 키** 기본 키가 될 수 있는 열의 묶음, 학번 말고 학생증 번호도 후보 키다
- **정규형** 표가 지켜야 할 조건의 단계, 수업에서는 제1부터 제3정규형까지 다룬다
- 주: 기호 →는 수업 교재 3장의 표기를 따른다

## 제3정규형까지 분해하고 다시 잇는 네 단계

- **1. 제1정규형** 한 칸에 값 하나만 둔다. 과목을 쉼표로 이어 적은 칸은 행으로 풀어 쓴다
  (1) 예: "DB101, ST201"이 적힌 칸 하나를 두 행으로 나눈다
  (2) 확인: 모든 칸이 더 쪼갤 수 없는 값 하나인지 본다
- **2. 제2정규형** 기본 키 일부에만 종속된 열을 떼어 낸다
  (1) 예: 학생(학번, 이름, 학과)과 과목(과목 코드, 과목명, 담당 교수)을 만든다
  (2) 확인: 남은 열이 (학번, 과목 코드) 전체에 종속되는지 본다
- **3. 제3정규형** 기본 키가 아닌 열끼리의 종속, 곧 이행 종속을 없앤다
  (1) 예: 담당 교수 → 연구실이 있으면 교수(교수명, 연구실) 표를 따로 둔다
  (2) 확인: 모든 열이 기본 키에만 직접 종속되는지 본다
- **4. 연결 표 만들기** 나눈 표를 잇는 수강(학번, 과목 코드) 표를 둔다
  (1) 예: 원본 5행이 수강 5행, 학생 3행, 과목 3행으로 나뉜다
  (2) 확인: 세 표를 조인하면 원본 5행이 그대로 다시 나오는지 본다
- 주: 분해한 뒤 수강(학번, 과목 코드) 표가 둘을 잇는다, 원본 5행의 정보는 하나도 사라지지 않는다

## 학생·수강·과목 세 표의 관계도

![도 1. 세 표의 관계도, 열쇠 모양은 기본 키 | 출처: 예시 이미지](assets/example-c.png)

- **학생** 학번이 기본 키, 학생 한 명에 한 행
- **과목** 과목 코드가 기본 키, 과목 하나에 한 행
- **수강** (학번, 과목 코드)가 기본 키, 신청 한 건에 한 행
- **관계** 학생 1명은 수강 여러 건, 과목 1개도 수강 여러 건을 가진다
- **저장량** 원본 표 30칸이 분해 후 25칸으로 줄고, 과목명은 한 번만 저장된다

## 내부 조인과 왼쪽 외부 조인 비교

:::: columns 1fr 1fr
::: col
- **내부 조인 (INNER JOIN)**
  (1) 결과: 두 표 모두에 짝이 있는 행만 남긴다
  (2) 예: 수강 신청이 있는 학생만 과목명과 함께 나온다
  (3) 행 수: 수강 표의 행 수와 같다, 예제에서 5행
  (4) 쓸 때: 실제로 신청한 내역을 볼 때
:::
::: col
- **왼쪽 외부 조인 (LEFT JOIN)**
  (1) 결과: 왼쪽 표의 행을 모두 남기고 짝이 없으면 빈칸으로 둔다
  (2) 예: 신청이 없는 학생도 과목명 빈칸으로 함께 나온다
  (3) 행 수: 수강 5행에 신청 없는 학생 수를 더한다
  (4) 쓸 때: 아직 신청하지 않은 학생을 찾을 때
:::
::::

## 조인에서 자주 하는 실수 세 가지

- **조인 조건 빠뜨리기**
  (1) ON 절을 빠뜨리면 두 표의 모든 행이 서로 짝지어진다
  (2) 학생 300명, 과목 40개면 결과가 1만 2천 행으로 불어난다
- **외부 조인 뒤 WHERE로 거르기**
  (1) 오른쪽 표 열을 WHERE에서 거르면 빈칸 행이 사라져 내부 조인과 같아진다
  (2) 조건을 ON 절로 옮기면 의도대로 남는다
- **지나친 분해**
  (1) 늘 함께 읽는 열까지 나누면 질의마다 조인이 늘어 느려진다
  (2) 제3정규형에서 멈추고, 성능 문제는 측정한 뒤에 다룬다

::: main-box
조인 결과의 행 수를 먼저 예상하고 실행한다. 예상보다 크게 늘었다면 조건 누락, 줄었다면 외부 조인이 내부 조인처럼 동작한 경우가 많다

예: 수강 5행을 학생 3행과 조인하면 결과도 5행이어야 한다. 3 × 5 = 15행이 나오면 ON 절이 빠진 것이다
:::

## 3강 요약과 다음 주 실습 과제

- 한 표에 모든 것을 담으면 같은 값이 반복되고 수정·삭제 때 자료가 어긋난다
- 함수 종속을 찾아 결정자마다 표를 나누면 제3정규형에 이른다
- 나눈 표는 조인으로 다시 합치고, 내부 조인과 왼쪽 외부 조인의 행 수 차이를 확인한다
- 과제: 동아리 회원 명부 표를 제3정규형으로 나누고 조인 질의 세 개를 작성한다
- 제출: 다음 주 수요일 자정까지 학습 관리 시스템에 SQL 파일 하나로 낸다, 채점은 설계 60점·질의 40점
- 다음 강의: 4강 인덱스와 실행 계획, 오늘 만든 세 표를 그대로 쓴다
