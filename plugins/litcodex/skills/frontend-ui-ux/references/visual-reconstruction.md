# Visual Reconstruction from Images

Use when screenshots, scans, or generated images are the primary implementation evidence.

## Observe before building

Inspect the image; record dimensions and hash. Separate visible geometry, color, text, alignment, and assets from inferred grid, semantics, type, and responsive rules. Treat interactions, hidden state, access, and backend behavior as unknown until independently checked.

Measure the frame, likely viewport, content bounds, anchors, spacing, type roles, color roles, surfaces, overlays, crops, and visible states. Prefer relationships to literal pixels; one frame cannot define every breakpoint.

## Reconstruct

Choose semantic structure by content and behavior, not appearance. For each asset reuse an authorized file, recreate with CSS/vector primitives, use a clearly approximate neutral asset, generate an authorized reference, or request a missing asset when identity depends on it. Do not extract or fabricate protected assets. Estimate font family, weight, size, line height, and measure separately; choose an available licensed fallback and keep approximation internal to the review record.

Preserve hierarchy, alignment, content priority, input access, and focal points at new widths. Treat responsive behavior as an inference to validate, not proof from the source image.

## Compare

Build structure, capture at the reference size, compare major regions, fix system causes before offsets, then review type, spacing, color, borders, and imagery. Exercise hidden states, other viewports, accessibility, and interactions. Record matched relationships, departures, inference, unavailable assets/fonts, and comparison evidence in the internal review note. Say “pixel perfect” only after controlled image comparison passes declared tolerances; mention one material fidelity gap once in the reply when it changes the decision.
