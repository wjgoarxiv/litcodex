# Brand and Imagery

Translate an approved brand into interface decisions; do not treat its assets as a finished system.

## Inputs

Use authorized purpose and audience, marks and clear-space rules, licensed color and type assets, voice guidance, imagery principles, existing product examples, accessibility, and platform constraints. If a material brand decision is missing, show bounded options.

| Quality | Interface expression |
| --- | --- |
| Precise | aligned layout, explicit labels, restrained transitions |
| Energetic | clear contrast, dynamic crops, quick feedback |
| Humane | readable type, forgiving recovery, warm content |
| Premium | restrained materials, deliberate pace, strong imagery |
| Technical | ordered density, visible state, exact units |

Logos and colors alone do not create a coherent product.

## Reference imagery

Use generated images for art direction, illustration concepts, textures, or environments when authorized. They do not define semantic markup, interaction, or accessibility. Prompts should specify purpose, aspect ratio, focal area, medium, palette, lighting, subject, space for real content, exclusions, and meaningful variation. Generate multiple directions only when the comparison can change a decision.

For full-screen concepts, state platform, viewport, safe areas, density, and interaction posture. Keep real text and controls in code. Reject pseudo-text, impossible geometry, inconsistent controls, and assets that cannot be used.

## Assets and identity

Record each accepted asset's source or license, generation details, crop, dimensions, format, compression, focal point, alt-text intent, and theme behavior. Remove unnecessary metadata; do not embed secrets or participant data. Test crops, contrast, missing-asset fallback, display density, and slow-network behavior.

Do not reproduce another product's marks, proprietary icons, or distinctive trade dress. Extract a general principle and express it in the product's own system. A named reference is evidence, not permission to copy.
