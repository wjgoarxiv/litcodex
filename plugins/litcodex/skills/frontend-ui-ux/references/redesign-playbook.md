# Existing-Product Redesign

Improve expression while protecting user tasks and known behavior.

## Baseline and debt

Before editing, capture routes, critical tasks and in-scope analytics, state/permission rules, components/tokens, access behavior, representative renders, performance, known defects, and current checks. Disliking a style does not establish a usability defect.

Track debt with ID, surface, observation, impact, cause, correction, risk, owner, and state. Separate visual, interaction, access, content, architecture, performance, and unverified concerns.

## Preserve or change

For each material behavior decide to preserve it, keep the outcome but improve presentation, change with approval, or remove because it is unreachable/unsupported with evidence. Do not silently rename concepts, reorganize navigation, or alter destructive behavior.

## Staged work

1. Capture a baseline.
2. Align tokens and primitives.
3. Correct component states.
4. Recompose one page family.
5. Compare behavior and renders.
6. Expand to remaining surfaces.
7. Remove legacy styles only after usage search and runtime checks.

Compare the same route, data, state, viewport, device scale, theme, locale, role, content, and capture method. Show regressions as well as gains.

When direction is disputed, present the actual options, users served, access effects, technical cost, and evidence. Record the choice rather than endlessly combining styles.

Recheck task completion, keyboard and screen-reader behavior, recovery, responsive transforms, localization, and performance. Update debt as resolved, accepted, deferred, or invalidated; temporary exceptions need an owner and review condition.
