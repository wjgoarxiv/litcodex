# Visual Language

Set rules for type, color, icons, imagery, surfaces, and data display from the product's content and tasks.

## Typography and color

Define roles for display, page and section titles, body, controls/metadata, data, and code. Choose type for script support, rendering, license, delivery cost, and voice. Test real text at narrow/wide measures, 200% zoom, bold, mixed Latin/CJK, punctuation, numbers, URLs, and user content. Do not assume a mockup font is installed.

Build semantic colors for surfaces, text, actions, selection, borders/focus, status, and charts. Check actual component states, including disabled and placeholder text. Color alone cannot carry status; reinforce it with labels, shape, pattern, or position. Reserve strong chroma for emphasis.

## Icons, imagery, surfaces

Choose a consistent icon stroke, optical size, corner, fill, and metaphor. Standalone controls need accessible names; check directional meaning in RTL. Do not use platform-dependent emoji as product icons.

Decide whether media is evidence, explanation, identity, atmosphere, or content. Specify crop, focal point, ratio, loading, alt text, and fallback. Decorative images use empty alt; informative text describes purpose. Keep essential localizable text out of images.

Build depth with spacing, tone, borders, and type before shadows. Tie a small elevation model to overlap; check contrast, compositing, fragmentation, and repeated radius choices.

## Data and review

Choose a form for the question: tables for exact values, lines for time, bars for magnitudes, histograms/boxes for distributions, scatterplots for relationships, and specialized diagrams for flow or hierarchy. Label units, axes, freshness, and missing data. Provide a text or table alternative for complex visuals; ensure patterns and annotations survive grayscale.

Check what attracts attention, what is interactive or dangerous, what belongs together, and what remains discoverable under errors, long text, low bandwidth, zoom, and preference changes. Revise when hierarchy depends on novelty alone.
